## Лаб 11
- Чем отличается запрет внешней записи от проверки допустимого числа? Где проверяются здоровье при создании и его изменение?
> Запрет внешней записи просто не дает присвоить иное значение для класса в коде программы без помощи методов этого класса. При создании здоровье проверяется в сеттере, а так как его изменение происходит с помощью методов класса то проверка осуществляется в самих методах если она реализована
- Как Name = name; связывает параметр конструктора, value и поле _name?
> value доступно в самом сеттере при объявлении поля, Name принимает проверенное значение. Напрямую Name не проверяется так как он бы тогда бесконечно вызывался геттером и поэтому для этого _name он без геттера. 
Какие значения в проверках показали, что правило 0 <= Health <= MaxHealth соблюдается?
> При некорректном изменении данных с помощью методов (например в лечение положить 10000) оно не позволяет так изменить данные и при выводе мы видим что данные остались корректные (например максимум 200 сделалось или здоровье не ушло в минус)


### Защита состояния Hero

Почему методы ПР №2 не защищали от прямой записи в поле:
> мы могли напрямую изменить параметры потому что они полностью публичные мы могли и получить данные и вписать их 

Чем отличаются get, set и private set:
> гет это получить данные (чтение) то есть мы обращаемся к указанному полю и получаем данные которые там лежат а сет позволяет изменять их или задавать. приватный сет не дает вне класса изменять указанное поле т.е напрямую из кода мы не можем изменить данные

Где проверяется начальное здоровье:
> начальное здоровье задается в сеттере и там же проверяется на корректность 

Как Heal сохраняет границу MaxHealth:
> лечение сверяетсяя с максздоровьем чтобы понять не выходим ли мы за предел и если да то просто оставляет доступный максимум а если нет то просто добавляем к текущему здоровью лечение

Как Name использует поле \_name и значение value:
> _name используется для того чтобы Имя не обращалось к самому себе бесконечное количество раз изза геттерa, а value это просто название доступной в гетсет переменной которую мы получаем в программе

Почему в конструкторе используется Name = name:
> В конструкторе есть свой name который вводит пользователь при использовании конструктора он никак не связан с _name он существует ток внутри конструктора

### Проверки

Конструктор: входные значения и полученные Health / MaxHealth:
- `new Hero("Проверка нижней границы", -100)` → `0/100`. Здоровье подтянулось к нулю, а предел заменился запасным значением `100`.
- `new Hero("Проверка верхней границы", 5000)` 

Урон и лечение: вызовы и фактические результаты:
Исходное состояние Александра: `150/150`.
- `TakeDamage(30)`, затем `Heal(10)` → `130`.
- `Heal(5000)` → `150`. Здоровье ограничено `MaxHealth`
- `Heal(-20)` → `150`. Отрицательное лечение игнорируется.


Имя: исходная строка и результат:
- `"   Александр   "` → `[Александр]`. Пробелы по краям удалены.
- `"   "` → `[Безымянный герой]`. Пустая или состоящая из пробелов строка заменена запасной подписью.

Какая внешняя запись не скомпилировалась и почему:
`alexander.Health = -100;` в `Program.cs`. Компилятор выдал ошибку у свойства `Health` объявлен `private set`, поэтому присваивать значение можно только внутри класса `Hero`. Запрет относится к доступу, а не к числу, так что даже допустимое значение присвоить нельзя

### Исправление ошибок

1. 
   Ошибка: `public int Health { get; set; }`. Открытый `set` позволяет из `Program.cs` записать `alexander.Health = -100;` и обойти все проверки  
   Исправление: `public int Health { get; private set; }`. Чтение осталось открытым, запись возможна только внутри `Hero`  
   Проверка: временная строка `alexander.Health = -100;` не компилируется. После её удаления `dotnet run` выводит четыре карточки, у Александра `150`.
2. 
   Ошибка: `value.Trim(); _name = value;`. `Trim()` возвращает новую строку, а результат нигде не сохранён, поэтому в `_name` попадает исходное значение с пробелами    
   Исправление: `_name = value.Trim();`  
   Проверка: `Hero nameCheck = new Hero("   Александр   ", 150);` и `Console.WriteLine($"[{nameCheck.Name}]");` выводят `[Александр]`
3. 
   Ошибка: в начале `Heal()` стояло `if (amount >= 0) { return; }`. Условие перепутано положительное лечение отклоняется, а отрицательное проходит дальше и уменьшает здоровье  
   Исправление: `if (amount <= 0) { return; }`.
   Проверка: для героя со здоровьем `100`  вызываем `TakeDamage(30)` (получается `70`), `Heal(10)` (`80`) и `Heal(-10)` (остаётся `80`)
4. 
   Ошибка: последняя строка `Heal()` была `Health -= amount;`. Лечение вычитает здоровье, а не прибавляет.  
   Исправление: `Health += amount;`  
   Проверка: на отдельном объекте со здоровьем `100` урон `30` и лечение `10` дают `80`. До исправления получалось `60`.
5. 
   Ошибка: в ветке полного восстановления было `Health = amount;`. Здоровье становится равным величине лечения, а не пределу, и может выйти за `MaxHealth`  
   Исправление: `Health = MaxHealth;`  
   Проверка: для героя с пределом `150` урон `30` и лечение `5000` дают `150`. До исправления получалось `5000`.

## дополнительные вопросы

1. Как открытое поле позволило обойти проверки `TakeDamage()`?

> проверки были только внутри метода а поле было public и любой код мог записать в него значение напрямую, `alexander.Health = 5000` просто меняло поле и метод даже не вызывался поэтому все правила в нём не сработали

2. Почему `{ get; set; }` само по себе не защитило здоровье?

> потому что это просто другая запись того же самого, `set` остался public и снаружи по-прежнему можно записать хоть 5000 хоть -100, свойство само никаких правил не придумывает их надо писать самому

3. Чем `private set` отличается от `private` у всего свойства?

> `private set` закрывает ток запись а читать здоровье можно отовсюду, а если сделать private всё свойство то из `Program.cs` нельзя будет даже прочитать значение

4. Почему конструктор может присвоить `Health`, а `Program.cs` — нет?

> `private set` разрешает запись только коду внутри класса `Hero`, конструктор и методы как раз внутри него а `Program.cs` снаружи поэтому там компилятор ругается 

5. Почему после ограничения записи всё равно понадобились проверки конструктора и лечения?

> `private set` решает кто может писать но не что именно, конструктор и `Heal` внутри класса и могут записать что угодно, без проверок `new Hero("...", -100)` дало бы -100 а `Heal(5000)` дало бы 5150

6. Где хранится имя, что делает `value` и зачем нужен `Trim()`?

> имя хранится в закрытом поле `_name`, а `Name` это свойство через которое с ним работают, `value` это то что присваивают свойству (при `Name = name` туда попадает содержимое `name`), `Trim()` убирает пробелы по краям 

7. Почему `_name = name;` в конструкторе обошло бы проверку имени?

> потому что проверка и `Trim()` лежат в `set` свойства `Name`, а если писать прямо в поле `_name` то `set` вообще не запускается и пробелы с пустой строкой пролезут как есть

8. Как `Heal()` сохраняет правило `0 <= Health <= MaxHealth`?

> сначала отбрасывает лечение <= 0, потом считает сколько не хватает до предела (`missingHealth = MaxHealth - Health`), если лечения хватает или больше то ставит ровно `MaxHealth` и выходит, иначе просто прибавляет, так выше предела не уйти, а снизу границу держит `TakeDamage`
